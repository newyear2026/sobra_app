# 저축 목표 (Mi meta)

작성일: 2026-11-05. 출발점은 사용자 리뷰 "뭔가 목표의식이 결여되네요 가계부쓴다는게".

## 현재 구현 — 2026-11-09

현재 구현된 범위는 **활성 목표 하나의 생성·수정·삭제·저장, 상품 링크 가져오기, 홈 진행 카드, 주기 마감 배정 팝업, 목표 달성 알림과 이력**입니다. 아래의 원래 제안과 다를 때는 이 절과 실제 코드가 최신 동작입니다.

- 홈의 기존 캐릭터 방 바로 **아래**에 12dp 간격으로 카드를 추가했습니다. 정사각형 방과 다섯 하단 메뉴는 변경하지 않습니다. 기존 문서의 방 위 배치 제안은 이 결정으로 대체합니다.
- 미설정 상태는 작은 `무엇을 위해 모으고 싶나요? / 목표 만들기` 진입 줄입니다. 누르면 **금액 목표 / 사고 싶은 물건** 중 하나를 선택합니다. 금액 목표는 사진·링크 없이 이름과 금액을 직접 입력하고, 상품 목표는 링크 가져오기나 직접 입력으로 만듭니다. 가짜 진행액이나 상품 사진을 넣지 않습니다.
- 목표 종류(`amount`/`product`)를 함께 저장합니다. 링크 없는 상품 목표도 선택한 종류를 유지하며, 상품 목표를 금액 목표로 바꾸면 상품 메타데이터만 제거합니다. 기존 이름·금액·날짜와 저축 진행 계산은 유지합니다. 종류 필드가 없는 이전 데이터는 상품 참조 유무로 안전하게 구분합니다.
- `1억 모으기`, 비상금, 여행 자금 같은 금액 목표도 지원합니다. 예를 들어 통화를 KRW로 설정한 테스트에서 100,000,000원 목표와 10,000,000원 시작 금액은 그대로 저장·복원되어 10%로 표시됩니다. 언어나 목표 이름을 보고 통화를 자동 변경하지 않습니다.
- Android/iOS의 앱 내 쇼핑몰 화면에서 사용자가 정보 가져오기를 누르면 사진·이름·가격 후보를 읽습니다. 보안 확인은 사용자가 직접 완료하며, 읽기 실패·지원하지 않는 플랫폼에서는 직접 입력할 수 있습니다. 가져온 금액은 수정·확인 후 저장하고 자동 갱신하지 않습니다. 통화가 다르거나 확인되지 않으면 목표 금액을 자동 입력하지 않습니다.
- 진행액은 시작 금액 + 목표 생성 이후 새로 기록한 저축 수입 + 사용자가 확인한 주기별 남은 생활비 배정액입니다. 생성 당시 기존 수입 ID를 제외해 같은 날 이미 모은 돈이 중복 계산되지 않습니다. 수입 수정·삭제가 진행액에 반영되며, 주기가 바뀌어도 목표를 유지합니다.
- 남은 생활비가 있는 가장 최근 마감 주기는 홈 위에 팝업을 한 번 표시합니다. 전액 또는 직접 정한 금액을 확인한 뒤 배정하며, 나중에/닫기는 배정하지 않습니다. 확인 여부는 재시작 후에도 유지됩니다. 레벨업이 있으면 먼저 표시하고, 선물·업데이트 등의 다른 팝업과 겹치지 않게 순서를 조정합니다.
- 목표가 없으면 팝업 → 기존 목표 생성 화면 → 해당 주기의 금액 확인 팝업 순서입니다. 목표 생성 취소 시 배정하지 않으며, 남은 생활비를 시작 금액에 자동으로 넣지 않습니다. 기존 목표가 이미 완료되었다면 다음 목표 생성으로 연결합니다.
- 같은 주기·같은 목표의 금액 변경은 덮어쓰기이며 중복 합산되지 않습니다. 마감 내역과 정산 화면에서 나중에 다시 열 수 있습니다. 이미 다른 목표에 배정한 돈은 목표 삭제·보관 후에도 예약으로 남아 재사용하지 않습니다.
- 과거 지출 수정으로 해당 주기의 잔여액이 줄면 활성 목표의 유효 배정액도 현재 잔여액 한도로 조정됩니다. 배정은 새 수입이나 은행 이체가 아니며, 생활비·현금·XP를 움직이지 않습니다.
- 진행액이 목표에 도달하면 축하 팝업을 한 번 표시하고 홈 카드에 체크·달성 완료·100%를 보여줍니다. 실제 누적액은 목표액을 넘더라도 그대로 표시합니다. 새 목표 저장 시 기존 완료 목표를 금액·달성 시각의 스냅샷으로 보관합니다. 새 목표 생성 취소 시 기존 목표를 유지합니다. 목표 화면 상단의 이력 버튼은 목표가 없을 때도 사용할 수 있습니다.
- 목표 저장·수정·삭제는 생활비, 현금 잔액, XP를 움직이지 않습니다. 저축 수입 기록은 기존 수입 기록 화면을 이용합니다.
- 목표는 스키마 12 백업에 포함되며 이전 스키마 백업도 읽습니다. 저장 실패 시 기존 메모리·디스크 상태로 되돌립니다.
- 팝업 구현 화면: `output/sobrita-goal-popup-implemented-20261109/`. 이전 이미지 시안은 `output/sobrita-goal-popup-ko-20261109/`에 보관합니다.
- 아직 포함하지 않은 확장 항목: 방 저금통 단계 그림, 목표 달성 XP, 목표 자금 인출. 아래 내용은 이 확장 항목들을 포함한 원래 설계입니다.

## 왜 필요한가

지금 앱에 있는 목표는 모두 앱이 정한 것이다.

- 오늘의 미션은 기록하는 행동에 보상한다 (`DailyMissionKind`: 기록, 같은 날 기록, 메모, 영수증).
- XP는 하루 한도와 초록 주기에 보상하지만 정산 때만 드러난다.
- `Guardarlo`(저축)로 넣은 돈은 `savedThisCycleCentavos`에 합산되지만 **무엇을 위해** 모으는지 적을 곳이 없다. 이번 주기가 끝나면 그 숫자도 화면에서 사라진다.

결국 "기록했다"는 보상만 있고 "그래서 내가 어디로 가고 있나"를 보여 주는 곳이 없다. 이 기능은 사용자가 직접 정한 목적 하나를 앱 한가운데에 둔다.

## 원칙

1. **활성 목표는 한 번에 하나.** 목표를 여러 개 두거나 버킷을 나누면 가계부가 자산관리 앱처럼 무거워진다.
2. **오늘 쓸 수 있는 돈에는 손대지 않는다.** `Hoy te queda`, 하루 한도, 카테고리 한도, 초록 주기 판정은 그대로 둔다. 고정지출을 예산에서 뺀 것과 같은 원칙이다.
3. **새 돈을 만들지 않는다.** 목표 진행액은 이미 지갑에 있는 돈에 붙이는 꼬리표다. 지갑 잔액(`expectedCashCentavos` 등)은 목표 때문에 움직이지 않는다.
4. **기록이 곧 진행이다.** 진행액은 저축 수입과 정산 때 보낸 sobrante에서 계산한다. 진행액을 따로 입력하는 화면은 두지 않는다.
5. **선택 사항이다.** 목표가 없어도 앱의 모든 기능은 지금처럼 동작한다.

## 데이터

코드에서는 `SavingsGoal`이라는 이름을 쓴다. `meta`로 쓰면 지금 브랜치(`feat/meta-app-events`)의 Meta SDK와 헷갈린다. 화면 문구만 "Meta"로 한다.

```dart
class SavingsGoal {
  final String id;
  final String name;              // "Viaje a Oaxaca", 최대 40자
  final int targetCentavos;       // > 0
  final int startingCentavos;     // 만들 때 이미 모아 둔 돈, 기본 0
  final DateTime createdAt;       // 이 날 이후의 저축 수입부터 센다
  final DateTime? targetDate;     // 선택
  final DateTime? reachedAt;      // 진행액이 처음 목표액에 닿은 날
  final DateTime? closedAt;       // 달성 후 정리했거나 포기한 날
  final SavingsGoalClosure? closure; // reached | abandoned
}

/// 정산 화면에서 sobrante를 목표로 보낸 기록. 지갑은 움직이지 않는다.
class GoalPledge {
  final String goalId;
  final String cycleKey;          // 정산된 주기의 yyyy-mm-dd 시작일. 주기당 한 번.
  final int amountCentavos;
  final DateTime at;
}
```

스토어(`SobraStore`)에는 다음을 둔다.

- `savingsGoals: List<SavingsGoal>`, `goalPledges: List<GoalPledge>`. JSON 키는 `savingsGoals`, `goalPledges`이고, 없으면 빈 목록으로 읽는다. 백업과 복원에도 그대로 들어간다.
- `activeGoal`: `closedAt == null`인 목표. 많아야 하나다.
- `goalProgressCentavos(goal)` = `startingCentavos`
  + `_incomes` 중 `allocation == savings`이고 `occurredAt`이 `createdAt` 날짜 이후인 것의 합
  + 그 목표에 묶인 `goalPledges`의 합.
  미션 보드가 XP 기록에서 계산되듯 진행액도 저장하지 않고 매번 계산한다. 그래서 저축 수입을 고치거나 지우면 진행액이 저절로 따라온다.
- 진행액은 목표액을 넘을 수 있다. 화면에는 100%로 표시하고 넘친 금액은 "+$X"로 보여 준다.
- `reachedAt`은 처음 목표에 닿은 순간 한 번만 기록한다. 그 뒤 저축 수입을 지워 진행액이 내려가도 달성 기록과 XP는 되돌리지 않는다.
- 통화를 바꾸면 `CycleRecord`처럼 금액을 환산하지 않고 표시 기호만 바꾼다.

### Sobrante 보내기의 경계

- 보낼 수 있는 금액은 그 주기 `resultCentavos`가 0보다 클 때, 0부터 그 값까지다.
- 같은 `cycleKey`로는 한 번만 보낸다. 다시 보내면 금액을 덮어쓴다.
- 나중에 과거 지출을 고쳐 그 주기 sobrante가 줄어도 이미 보낸 금액은 그대로 둔다. 다만 cycle history 상세에서 "보낸 금액 > 지금 sobrante"이면 금액을 고칠 수 있는 줄을 보여 준다.
- `closedCyclesResultCentavos`("Lo que te sobró en ciclos anteriores")는 바꾸지 않는다. 보낸 sobrante도 그 안에 이미 들어 있다.

## 화면

시안: `design/savings-goal/` (전체 모음 `00-overview.png`). 앱 위젯과 폰트로 그린 golden이다 (`test/savings_goal_proposal_test.dart`). 저금통 단계 그림은 `tool/build_savings_jar_stages.py`로 기존 저금통에서 만든 임시 아트다.

### Inicio: 목표 카드

- 위치: `_HomeProjection` 바로 아래. 주기 전망("이 속도면 ~ 남아요") 다음에 "그 돈이 어디로 가는지"를 보여 준다.
- 내용: 목표 이름, 진행 막대, `$1,250 / $5,000`, 퍼센트.
- `targetDate`가 있으면 한 줄을 더 둔다: **"marzo까지 주기마다 $X"**. 남은 금액을 그날까지 남은 주기 수로 나눈 값이다 (주기 경계는 지금 pay schedule 기준). 이 문장이 "왜 오늘 아껴야 하는지"를 숫자로 보여 주는 핵심이다.
- 카드를 누르면 목표 상세(수정, 내역, 포기)가 열린다.
- 목표가 없을 때는 같은 자리에 작은 빈 카드("¿Para qué estás ahorrando?" + 만들기)를 둔다. 조건: 예산이 있고 첫 기록을 한 뒤, 그리고 사용자가 닫지 않았을 때. 닫으면 Presupuesto 탭 진입점만 남긴다.

### Presupuesto: 저축 카드

이미 있는 저축 줄(`budgetSavedThisCycle`, `budgetClosedCyclesResult`) 아래에 목표 진행 한 줄을 추가한다. 목표가 없으면 여기에 "목표 만들기" 링크를 둔다.

### 기록: `Guardarlo` 선택지

저축 수입을 고를 때 활성 목표가 있으면 칩 아래에 "→ Viaje a Oaxaca"를 작게 보여 준다. 저장 토스트에는 "Viaje a Oaxaca · 25% → 31%"를 띄운다. 기록하는 순간 진행이 보여야 한다.

현금 세기(`cash_count_screen`)에서 남는 돈을 저축으로 넣을 때도 같은 규칙으로 목표에 들어간다. 저축 수입으로 기록되기 때문에 추가 작업은 없다.

### 정산: sobrante 보내기

`SettlementScreen`의 Sobrante 줄 아래, sobrante가 있고 활성 목표가 있을 때만 보인다.

- 버튼: **"Mandar $X a tu meta"** (기본값은 sobrante 전액). 옆에 금액 고치기.
- 보낸 뒤: "Viaje a Oaxaca · 40% → 52%"와 저금통이 차오르는 짧은 장면.
- 이미 있는 `settlementCtaTitle`(컬렉션 유도)은 그 아래로 내린다.

주기를 마감하는 순간이 "아낀 돈이 내 목표가 되는" 장면이 된다. 이 기능의 중심 루프다.

### 방: 저금통

- `RoomDecorAssets.savingsJar`는 모든 사용자에게 `included`이고, `room_decorate`에는 이미 `roomSuggestSavingsJar` 제안이 있다.
- 활성 목표가 있으면 저금통 스프라이트를 진행률 단계(0 / 25 / 50 / 75 / 100%)에 맞춰 바꾼다. 같은 크기와 기준점의 프레임 5장이 필요하다. 목표가 없으면 지금 그림(기본 프레임)을 쓴다.
- 저금통이 방에 없으면 목표 상세에 "방에 저금통 놓기" 버튼을 두고 `room_decorate`의 기존 제안으로 연결한다.
- 위젯은 시스템 폰트와 비트맵 문제가 있어 v1에서 제외한다.

### 달성

- 진행액이 목표액에 처음 닿으면 기존 축하 장면을 재사용해 "¡Lo lograste!"를 띄운다.
- 그다음 고를 수 있다: **계속 모으기**(목표액 올리기) / **정리하기**(`closure = reached`, 새 목표 만들기로 이동).
- 달성한 목표는 목표 상세의 "지난 목표" 목록에 이름, 금액, 걸린 기간과 함께 남는다.

## XP

| 이벤트 | XP | 조건 |
| --- | --- | --- |
| 목표 달성 | 50 | 목표당 한 번, 만든 지 7일 이상, sourceKey `goal-reached:<id>` |

목표를 만들거나 저축하는 행동 자체에는 XP를 주지 않는다. 그렇게 하면 작은 목표를 만들었다 지우거나 가짜 저축 수입을 넣어 XP를 모으는 길이 생긴다. 달성 XP도 "7일 이상" 조건과 목표당 한 번 제한으로 막는다.

미션 풀에는 목표 미션을 넣지 않는다. `DailyMissionKind.forDay`는 날짜만으로 보드를 정하는데 (풀 크기 2, 3이 서로소), 목표 유무에 따라 풀이 달라지면 이 결정성이 깨진다.

## 텔레메트리

`TelemetryEvent`에 다음을 추가한다.

- `goalCreated('goal_created')`: `has_date`, `target_bucket` (금액은 구간으로만)
- `goalPledged('goal_pledged')`: 정산에서 보냈는지 여부와 sobrante 대비 비율 구간
- `goalReached('goal_reached')`: `days_to_reach` 구간
- `goalClosed('goal_closed')`: `closure`

Meta app events로 보낼 후보는 `goal_created`다. 의도가 드러나는 사용자 신호다.

볼 지표: 목표를 만든 사용자와 만들지 않은 사용자의 D30 유지율, 그리고 정산 화면에서 보내기를 누른 비율.

## 구현 순서

1. 모델, 스토어, JSON, 백업. 진행액 계산과 sobrante 보내기의 단위 테스트 (경계: 수입 수정·삭제, `createdAt` 이전 날짜의 수입, 같은 주기에 두 번 보내기, 통화 변경).
2. 목표 만들기·수정 시트와 목표 상세 화면.
3. Inicio 카드, Presupuesto 줄, 기록 칩과 토스트.
4. 정산 보내기.
5. 저금통 프레임 5장 (아트 작업은 병행 가능).
6. 달성 축하, XP, 텔레메트리, 문구 7개 언어.

## 열린 질문

- **목표 돈을 쓸 때.** 여행 경비를 일반 지출로 기록하면 그 주기 예산을 깎아 버린다. 고정지출 결제처럼 예산 밖 지출(`isFixedPayment`과 같은 경로)로 "목표에서 쓰기"를 둘지, v1에서는 "정리하기"만 둘지 정해야 한다. v1은 정리하기만 두는 쪽을 권한다.
- 목표를 만들 때 지난 저축 수입 전체를 시작 금액으로 제안할지 (예: "Ya llevas $3,200 guardados. ¿Los cuentas?").
- 빈 카드 노출 시점을 첫 기록 직후로 할지, 첫 정산 이후로 할지.
