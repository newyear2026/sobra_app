# Play Console 적용 체크리스트 — 스토어 등록정보 다국어

Sobrita는 앱 UI를 7개 언어로 번역해 뒀는데(`lib/l10n/app_{de,en,es,fr,ja,ko,pt}.arb`)
Play 스토어 등록정보는 일부 로케일에만 채워져 있어요. Play는 **문안을 채운 로케일에서만**
그 언어로 리스팅을 노출하고 색인해요. 비어 있는 로케일은 기본 언어 문안이 그대로 보이고,
그 언어 키워드로는 검색에 안 걸려요.

문안 파일은 로케일당 하나예요. Play Console에 넣을 때도 **한 번에 한 파일, 한 로케일**만 열어요.

| 로케일 | 문안 파일 | 상태 |
| --- | --- | --- |
| es-419 | `listing-es-419.md` | 라이브로 추정 → **문안 교체** |
| pt-BR | `listing-pt-BR.md` | 기존 문서 있음 → 적용 여부 확인 |
| en-US | `listing-en-US.md` | **로케일 추가** 가능성 높음 |
| ko-KR | `listing-ko-KR.md` | **로케일 추가** 가능성 높음 |
| ja-JP | `listing-ja-JP.md` | **로케일 추가** 가능성 높음 |
| de-DE | `listing-de-DE.md` | **로케일 추가** 가능성 높음 |
| fr-FR | `listing-fr-FR.md` | **로케일 추가** 가능성 높음 |

"추정"이라고 쓴 이유: 저장소에는 Play Console의 현재 상태가 없어요. 0단계에서 직접 확인해요.

---

## 0단계 — 먼저 현재 상태를 확인해요 (작업 전 1회)

1. Play Console → **앱 → 성장 → 스토어 설정 → 기본 스토어 등록정보**로 들어가요.
2. 페이지 위쪽 **언어 드롭다운**을 열어요. 거기 떠 있는 목록이 **이미 추가된 로케일**이에요.
   목록에 없으면 "로케일 추가", 있으면 "문안 교체"예요.
3. **기본 언어(default language)가 무엇인지 적어 둬요.** `listing-pt-BR.md`를 보면 es-419를
   바탕으로 썼다고 되어 있어서 es-419가 기본 언어일 가능성이 높아요.
   기본 언어는 **바꾸지 않아요.** 바꾸면 비어 있는 모든 나라에서 보이는 문안이 통째로 달라져요.
4. 이미 들어가 있는 로케일은 **현재 문안(앱 이름 / 간단한 설명 / 자세한 설명)을 그대로 복사해
   어딘가에 붙여 둬요.** 되돌릴 때 필요해요. Play Console에는 이전 문안 기록이 남지 않아요.

---

## 1단계 — 순서

앞의 것이 뒤의 것보다 효과가 커요. 이 순서대로 해요.

1. **en-US** — 영어는 문안을 채우지 않은 나라의 기본 fallback이 되기 쉬워요. 하나 채우면
   여러 나라에 동시에 걸려요. 기본 언어가 es-419라면 en-US는 "추가"예요.
2. **es-419** — 이미 라이브라면 "교체"예요. 0단계에서 현재 문안을 복사해 두고 비교한 뒤에 바꿔요.
   지금 들어가 있는 문안이 더 좋을 수도 있으니, 앱 이름까지 통째로 바꾸기 전에 한 번 더 봐요.
3. **pt-BR** — `listing-pt-BR.md`가 이미 있어요. 적용돼 있으면 건드리지 않아요. 안 돼 있으면 추가해요.
4. **ko-KR**, **ja-JP** — 앱이 이미 완전히 번역돼 있고, 두 나라 다 카테고리 대표어가
   뚜렷해요(가계부 / 家計簿). 들인 노력 대비 효과가 커요.
5. **de-DE**, **fr-FR** — 마지막. 같은 이유로 가치는 있지만 경쟁이 더 심해요.

**한 번에 다 올리지 마세요.** 2~3일 간격으로 하나씩 올려야 어느 로케일이 설치 수를 움직였는지
알 수 있어요. 모두 같은 날 바꾸면 원인을 구분할 수 없어요.

---

## 2단계 — "로케일 추가"일 때 (목록에 없는 언어)

1. 기본 스토어 등록정보 → 언어 드롭다운 → **번역 관리 / 언어 추가**에서 로케일을 골라요.
   - 스페인어는 **es-419(라틴아메리카)**, es-ES(스페인)이 아니에요. 앱 안 스페인어가
     라틴아메리카 말이에요(`Renta`, `celular`, `luz`).
   - 포르투갈어는 **pt-BR(브라질)**이에요.
2. 추가한 로케일을 고른 다음, 해당 `listing-<로케일>.md` **하나만** 열어요.
3. 코드 블록을 입력란 하나에 하나씩 붙여넣어요. 순서: 앱 이름 → 간단한 설명 → 자세한 설명.
   - **코드 블록 안의 내용만** 복사해요. `(22/30자)` 같은 괄호는 붙여넣지 않아요.
   - 추천안과 대안이 둘 다 있으면 **추천안**을 써요. 대안은 나중에 A/B로 바꿔 볼 때 쓰는 거예요.
4. 그래픽 이미지와 스크린샷은 **비워 둬요.** 비우면 기본 언어 이미지가 그대로 나와요.
   문안만 채워도 색인은 돼요.
5. 저장 → 검토 제출. 문안 변경은 검토를 거쳐요(보통 몇 시간~며칠).

## 3단계 — "문안 교체"일 때 (목록에 이미 있는 언어)

1. 바꾸기 전에 **현재 문안 세 칸을 전부 복사해 둬요.** 되돌릴 방법은 이것뿐이에요.
2. 입력란을 **전부 지운 뒤에** 새 문안을 붙여넣어요. 덧붙이지 말고요.
   - RandomFocus에서 실제로 났던 사고예요: 라이브 ko-KR 자세한 설명 칸에 한국어와 깨진
     스페인어가 같이 들어가 있었어요. 여러 언어를 한 문서에서 복사하다 섞인 거예요.
     그래서 이 작업은 로케일당 파일 하나로 나눠 놨어요.
3. 붙여넣은 뒤 **입력란 옆 글자 수 카운터**가 문안 파일에 적힌 숫자와 같은지 확인해요.
   다르면 앞뒤에 뭔가 묻어 들어간 거예요.
4. 저장 → 검토 제출.

---

## 4단계 — 올린 뒤 확인

- 검토가 끝나면 **해당 언어로 설정한 기기나 `?hl=` 파라미터**로 스토어 페이지를 열어 확인해요.
  예: `https://play.google.com/store/apps/details?id=com.sobra.app.sobra_app&hl=de`
- 앱 이름이 의도한 대로 나오는지, 자세한 설명 첫 두 줄이 잘리지 않는지 봐요.
  Play는 자세한 설명 앞부분만 접힌 상태로 보여줘요.
- 2~4주 뒤 **Play Console → 통계 → 사용자 획득 → 검색어**에서 그 언어 검색어가 잡히는지 봐요.
  색인에 반영되기까지 시간이 걸려요. 하루 이틀 보고 판단하지 않아요.

---

## 같이 봐 둘 것

- **앱 이름을 바꾸면 Google Ads에 영향이 가요.** 광고를 보고 스토어에서 브랜드명을 검색하는
  경로가 있어서, 로케일마다 이름이 달라지면 못 찾는 사람이 생겨요.
  그래서 모든 문안에서 `Sobrita`를 앞에 그대로 두고, 뒤에만 그 언어 키워드를 붙였어요.
  한국어·일본어도 음차하지 않았어요.
- **출시 노트(What's new)는 별개예요.** `play-whats-new-1.0.16.md`가 따로 담당해요.
  스토어 등록정보를 바꿔도 출시 노트는 안 바뀌어요.
- **스토어 등록정보 로케일과 APK 지원 언어는 별개예요.** 등록정보에 로케일을 추가한다고
  앱이 그 언어를 더 지원하게 되는 건 아니고, 반대도 마찬가지예요. 지금은 앱 쪽이 7개 언어로
  먼저 가 있고 등록정보가 따라가는 중이에요.
- 지금 스크린샷의 큰 제목은 스페인어예요. 여유가 생기면 `build_screenshots.py`에 로케일별
  문구를 추가하고 `capture.py`로 다시 찍어요. 문안보다 우선순위는 낮아요.
