# Sobra 광고 · 수익화 기준 문서

> 이 문서가 광고와 수익화의 **단일 기준**입니다.
> `design/ads/ad-placements.html` 등 시안 이미지는 이 문서를 시각화한 보조 자료이며,
> 내용이 충돌하면 **언제나 이 문서가 우선**합니다.
> 숫자·문구를 바꿀 때는 이 문서를 먼저 고치고 시안을 다시 그립니다.

최종 갱신: 2026-09-18

---

## 0. 확정된 원칙

1. **강제 전면 광고를 두지 않는다.** 모든 광고는 사용자가 선택해 시작한다.
2. **보상형 광고의 진입점은 `CollectionScreen` 한 곳뿐이다.** 로딩·하루 제한·진행도·실패 처리를 한 군데서 관리한다.
3. **v1은 보상형 + 캐릭터 판매만, 네이티브와 광고 제거 상품은 v1.1.** 제거할 광고가 없는 상태로 광고 제거 상품을 팔지 않는다.
4. **노출 집계는 SDK의 `onAdImpression` 기준.** 자체 가시성 감지기를 만들지 않는다.
5. **카탈로그 엔트리의 해금 경로는 하나로 유지한다.** `CatalogUnlockMethod`를 경로 집합으로 바꾸는 재설계는 하지 않는다.

### 수익 모델에 대한 의사결정

> Sobra의 광고는 직접적인 주 수익원이 아니라 무료 사용자의 운영비 보조 수단이다.
> 주 수익원은 캐릭터 IAP와 `미치와 친구들` 팩이며,
> 유지율과 금융 데이터에 대한 신뢰를 광고 노출량보다 우선한다.

이 구성의 광고 매출은 의도적으로 낮습니다. 사고가 아니라 결정입니다.

## 2. 보상형 광고

### 진입점

`CollectionScreen`에서 사용자가 직접 시작할 때만 재생합니다. 다른 화면에서는 재생하지 않습니다.

### 해금 비용

| 대상 | 필요 광고 | 목적 |
| --- | --- | --- |
| 방 아이템 | 1회 | 가격 |
| 일반 캐릭터 | 2회 | 가격 |
| 특별 캐릭터 | 서로 다른 날 3회 | **재방문 장치 (가격 아님)** |

- 가격은 **하루 상한을 다시 켜더라도 그보다 낮아야 합니다.** 캐릭터 2 + 아이템 1 = 3이라 상한 3에 맞습니다. 테스트가 이 여유를 지킵니다.
- 특별 캐릭터의 3은 "광고를 세 번 보게 하려는 것"이 아니라 "사흘에 걸쳐 돌아오게 하려는 것"입니다. 이 둘을 같은 축에서 조정하지 마십시오.
- 값은 엔트리별 `rewardedAdTarget`에 있습니다. **원격 설정으로 덮어쓸 수 있게 만들어**, 출시 후 완주율을 보고 릴리즈 없이 조정합니다.

### 제한과 실패

- 전체 보상형 광고: **하루 한도 없음** (2026-09-15 변경, 아래 참조)
- 중도 종료·로드 실패: **진행도 증가 없음**
- 사용 가능한 광고가 없으면 버튼을 `현재 광고 없음`으로 비활성화
- 진행도는 **만료되지 않습니다.** 영구 보존합니다.
- 보상은 SDK의 보상 콜백에서만 지급하고, 중복 호출에 대비해 멱등하게 처리합니다.
- `일반 광고 제거` 구매자도 보상형 광고는 선택적으로 계속 이용할 수 있습니다.

### 하루 한도를 두지 않는 이유 (2026-09-15 결정)

기존 `하루 최대 3회`를 없앴습니다.

- **정책 요구가 아닙니다.** 보상형은 사용자가 매번 직접 시작하는 형식이라 일일 한도를 요구하지 않습니다.
- **수익을 줄입니다.** 한도는 노출을 깎습니다.
- **사용자 보호도 약합니다.** 스스로 누른 행동을 막는 것이고, `오늘 한도 도달`은 Sobra가 하고 싶어 하는 사용자에게 거절하는 **유일한** 자리였습니다. "광고는 사용자가 선택한다"는 0절 원칙과 어긋납니다.
- **페이싱 효과가 하루뿐이었습니다.** 보상형 전체가 10편이고, 특별 티어가 이미 3일을 강제합니다. 한도 없이 3일, 한도 3편으로 4일 — **카탈로그 자체가 진짜 한도**입니다.

**메커니즘은 남겼습니다.** `SobraStore.load(rewardedAdsPerDay: …)`로 켤 수 있고, 기본값은 `null`(없음)입니다. 상수가 아니라 주입 값으로 둔 이유는 **한도 동작이 계속 테스트로 덮이게 하기 위해서**입니다 — 아무도 도달할 수 없는 경로는 조용히 망가집니다.

되살릴 조건: **보상형 엔트리를 업데이트로 계속 추가하기로 하면** 페이싱이 다시 필요해지고, 그때는 숫자 하나입니다.

> 일일 카운트(`rewardedAdsWatchedToday`)는 한도가 없어도 계속 셉니다. 특별 티어가 쓰는 날짜 키를 공유하므로 비용이 없고, 나중에 한도를 켤 때 빈 이력에서 시작하지 않습니다.

### 결산 화면

결산 화면은 **광고를 재생하지 않습니다.** 보상 유도 카드만 둡니다.

```
결산 완료
→ [특별 꾸미기 받으러 가기]
→ CollectionScreen 열기 + 추천 엔트리 상세 표시
→ 컬렉션에서만 보상형 광고 실행
```

추천 엔트리 우선순위:

1. 이미 광고 진행도가 있는 엔트리
2. 필요한 광고 횟수가 가장 적은 엔트리
3. 카탈로그 표시 순서가 빠른 엔트리

**카드를 렌더링하지 않는 조건 (둘 중 하나라도 해당):**

- 하루 상한 3회를 이미 소진함
- 해금 가능한 보상형 엔트리가 하나도 남지 않음

비활성화하지 말고 **아예 숨깁니다.** 축하 화면 직후의 회색 버튼은 최악의 순간입니다.

구현: `settleCycles()`가 주기를 닫으면 `AppShell`이 `SettlementScreen`을 연다.
카드는 `SobraStore.recommendedRewardedAdEntry`가 있을 때만 그린다.
탭하면 `CollectionScreen(initialEntryId: …)`로 가고, 광고는 컬렉션 상세에서만 재생한다.
설정에서 여는 컬렉션은 추천이 없으므로 `const CollectionScreen()`을 유지한다.

설정 상점의 진행도는 카드에 싣지 않는다. 컬렉션 상세 다이얼로그가 진행도를 보여 준다.

## 3. 네이티브 광고 (v1.1)

### 삽입 규칙

> 현재 필터 결과에 실제 거래 행이 8건 이상 있을 때만,
> 8번째 거래 행 다음에 네이티브 광고 슬롯을 삽입한다.
> 날짜 헤더·요약·그래프·빈 상태는 거래 행 수에 포함하지 않는다.

- 8번째 거래가 날짜 그룹의 마지막이면 **날짜 그룹을 닫은 후** 광고 표시
- 거래가 정확히 8건이어도 맨 아래 광고 허용. 단, 효율이 낮으면 원격 플래그로 비활성화 가능
- 광고 로드 실패 시 **슬롯 전체 제거** (빈 자리를 남기지 않음)

### 노출 제한

> 하루 최대 2회이며, 같은 방문에서는 1회를 넘지 않는다.

두 조건은 경쟁 규칙이 아니라 **동시에 만족해야 하는 상한**입니다.

- **로드됐다는 이유만으로 한도를 소비하지 않습니다.**
- SDK의 **`onAdImpression`이 호출됐을 때** 방문·일일 노출 횟수를 증가시킵니다.
- 첫 설치 후 **7일 동안 미노출**
- `일반 광고 제거` 구매자·팩 구매자 **미노출**

### 방문의 정의

> 거래 내역 탭이 **비선택 상태에서 선택 상태로 전환될 때** 방문 1회를 시작한다.

- 같은 방문에서 필터를 바꾸거나 스크롤을 반복해도 추가 광고를 표시하지 않습니다.
- 세션 개념(백그라운드 복귀 시간 등)은 **쓰지 않습니다.** 하루 2회 상한이 실질적인 상한 역할을 합니다.

**구현 주의:**

- `app_shell.dart` 는 `IndexedStack`이라 화면이 계속 마운트되어 있습니다. `initState()`로 세면 안 됩니다.
- 갱신 지점은 `app_shell.dart:179` `_select(AppTab tab)` 입니다.
- `_select`는 **같은 탭 재탭도 그대로 통과**하므로 `tab != _selected` 가드가 필요합니다. 없으면 활성 탭을 다시 누를 때마다 방문이 증가합니다.
- 탭이 바뀌는 자리가 하나 더 있습니다 — `app_shell.dart:123`(홈으로 강제 이동). 방문 갱신은 두 지점을 모두 타야 합니다.

### 표시 형식

- 실제 거래 행과 **다른 전체 너비 카드**
- 금액·시간·카테고리 표시 **금지**
- `광고` 라벨과 AdChoices 명시
- CTA 문구는 네트워크가 제공합니다. 시안의 `자세히 보기` / `설치`는 예시일 뿐 고정값이 아닙니다.

## 4. 동의 흐름

```
앱 실행
→ UMP 동의 상태 확인
→ 필요한 지역에 동의 폼 표시
→ 추적 기능을 사용하는 iOS 사용자에게만 ATT 요청
→ 광고 요청 가능 상태 확인
→ 광고 미리 로드
```

- **ATT는 광고 SDK를 넣었다고 무조건 띄우는 것이 아닙니다.** 다른 회사의 앱·웹을 가로지르는 추적을 할 때만 필요합니다. IDFA를 쓰지 않는 제한 광고라면 ATT 없이도 광고를 요청할 수 있습니다.
- ATT를 요청하기로 하면 `NSUserTrackingUsageDescription`이 필요합니다.
- 광고 SDK 초기화는 **동의 수집 이후**에 합니다.
- `privacyOptionsRequirementStatus`가 required인 사용자에게는 **상시 접근 가능한 진입점**을 제공해야 합니다. 구매 항목이 아니라 별도 `개인정보` 섹션에 둡니다.

## 5. 상품과 권리

### 미치와 친구들 (v1)

```
미치와 친구들
캐릭터 3종 + 미치의 별
1회 결제
```

- 상품명은 **파는 것을 그대로 서술합니다.** 재화를 전달하는 판매를 `후원`이라 부르지 않습니다. 순수 기부는 IAP로 받을 수 없고, 내용물을 앞세우는 것이 그 선을 지키는 방법이기도 합니다.
- **현재 존재하지 않는 광고 제거를 상품명이나 핵심 가치로 앞세우지 않습니다.**
- 상세 설명 하단에만 고지: `구매자는 향후 일반 광고가 도입되어도 광고 없이 이용할 수 있습니다.`
- **중복 고지는 필요 없습니다.** 팩에 든 캐릭터는 개별로 팔지 않으므로 겹쳐 사는 경로가 존재하지 않습니다. 아래 카탈로그 경로를 바꾼다면 이 고지를 되살려야 합니다.

### 일반 광고 제거 (v1.1)

```
일반 광고 제거
1회 결제 · 영구 적용

거래 내역의 일반 광고가 제거됩니다.
보상을 위한 선택형 광고는 계속 이용할 수 있습니다.
```

### 권리 매핑

```dart
const productEntitlements = {
  'sobra.supporter.bundle': {
    'character-02',
    'character-04',
    'character-06',
    'supporter-decoration',
    'entitlement.no_ads',
  },
  'sobra.ads.remove': {
    'entitlement.no_ads',
  },
};
```

**필수 구현 사항:**

1. **`productEntitlements` 검사가 `CatalogPreviewData.entryForProductId()`보다 먼저**여야 합니다.
   `entryForProductId`(`catalog_preview_data.dart:192`)는 `storeProductId`가 일치하는 **첫 엔트리 하나만** 반환합니다. 번들 ID를 가진 엔트리가 먼저 잡히면 팩 구매가 그 하나만 지급하고 끝납니다. 팩 전용 캐릭터도 같은 ID를 지니게 되었으므로 이제 먼저 잡히는 것은 `character-02`입니다.

2. **일괄 지급 메서드**가 필요합니다. 하나씩 저장하면 일부만 지급된 상태가 남습니다.

   ```dart
   Future<void> grantCatalogEntries(Set<String> ids) async {
     final added = ids.where((id) => id.isNotEmpty).toSet()
       ..removeAll(_ownedCatalogIds);
     if (added.isEmpty) return;
     _ownedCatalogIds.addAll(added);
     _rewardedAdProgress.removeWhere((id, _) => added.contains(id));
     await _save();
     notifyListeners();
   }
   ```

   구현됨 — `sobra_store.dart`. `grantCatalogEntry`는 여기에 위임합니다.

   `ids.where(_ownedCatalogIds.add)` 형태는 쓰지 마십시오. `where`가 lazy라 `.toList()`가 유일하게 부작용을 강제하며, 나중에 그것을 제거해도 컴파일과 테스트가 통과합니다.

3. 오류 처리는 기존 `_grant`(`purchase_service.dart:359`)와 동일하게 — 낙관적 갱신 + `try/catch` + 다음 실행에 재지급.

4. **복원 시에도 같은 집합을 다시 지급**합니다.

5. 알 수 없는 상품 ID를 그대로 저장하는 기존 fallback(`entry?.id ?? productId`)은 구버전 상품 복원을 위한 의도적 동작이므로 **제거하지 않습니다.** 대신 **알려진 번들 상품이 반드시 매핑되어 있는지 테스트로 보장**합니다. 현재 상태로 번들 ID를 넣으면 결제와 저장이 모두 성공하고 캐릭터는 하나도 지급되지 않습니다 — 조용한 실패입니다.

| 구매 전용 캐릭터 | 개별 구매로만 (07 · 09 · 10) |
| 레벨 전용 아이템 | 레벨로만 |

- 보상형 전용 캐릭터에 현금 우회 구매는 **제공하지 않습니다.** `CatalogUnlockMethod`(`catalog_entry.dart:7`)가 엔트리당 하나이므로 모델 재설계가 필요하고, 초기 버전에는 불필요합니다.
- 캐릭터를 개별 구매해도 **일반 광고는 제거되지 않습니다.** 광고 제거는 `일반 광고 제거`와 `미치와 친구들`에만 따라옵니다.
- **한 캐릭터가 두 경로로 팔리지 않습니다.** 팩에 든 것을 개별로도 팔면, 하나를 사고 팩을 산 사람이 같은 캐릭터를 두 번 결제합니다. `grantCatalogEntries`는 이미 가진 id를 조용히 버리고 스토어는 그 차액을 환불하지 않습니다. `catalog_entitlement_test.dart`가 이 규칙을 지킵니다.

### `supporter-decoration`(미치의 별) 표시 규칙

카탈로그에 추가하는 순간 `CollectionScreen`(`collection_screen.dart:155`)이 카탈로그를 순회하므로 **미구매자에게도 보입니다.**

- 잠김 상태로 노출하되, 개별 구매 버튼 대신 `미치와 친구들에 들어 있어요` 안내만 표시합니다.
- 장식 하나 옆에 팩 전체 가격이 붙는 상황을 피합니다.
- 같은 규칙이 팩 전용 캐릭터 3종에도 적용됩니다. `collection_screen.dart`가 가격과 구매 버튼을 `unlockMethod`로 막으므로 별도 처리는 필요 없습니다.

> `supporter-decoration`과 `sobra.supporter.bundle`이라는 **문자열 값은 이름이 바뀐 뒤에도 그대로 둡니다.** 전자는 이미 저장된 소유 집합의 키이고, 후자는 스토어 콘솔에 등록되면 재사용이 불가능합니다. 값을 바꾸는 것은 편집이 아니라 마이그레이션입니다.

> 참고: `entitlement.no_ads`처럼 카탈로그에 없는 문자열을 소유 집합에 넣는 것은 안전합니다.
> 컬렉션은 소유 집합이 아니라 카탈로그를 순회하므로 유령 항목이 생기지 않습니다.

## 6. 금액 표시

통화는 **MXN** 하나로 통일합니다.

```
문서 표기   : MX$6,800
현재 앱 출력: $6,800 MXN
스토어 가격 : 플랫폼이 반환한 현지화 문자열 (직접 만들지 않음)
```

- 앱은 `NumberFormat.currency`를 쓰지 않습니다. 자체 `formatMoney()`(`pixel_ui.dart:39`)가 `{기호}{정수}{.소수} {코드}` 형태로 출력합니다.
- 금액은 이미 전부 `int minorUnits`(centavo)로 저장·계산됩니다. **마이그레이션이 필요 없습니다.**
- `formatMoney()`는 centavo가 0일 때만 소수를 생략합니다. 따라서 **전면 반올림 규칙을 넣으면 모든 화면의 거래 금액 표시가 바뀝니다.**

**규칙:**

| 대상 | 처리 |
| --- | --- |
| 실제 거래 금액 | 그대로. centavo가 있으면 표시 (`$45.50 MXN`) |
| 파생 통계(일평균 등) | 100 minor units 단위로 반올림한 뒤 `formatMoney()`에 전달 |

`formatMoney()` 자체는 변경하지 않습니다.

```dart
final roundedAverageCentavos =
    ((spentCentavos / elapsedDays) / 100).round() * 100;
```

### 일평균 지출

```
종료된 주기   : 총 지출 ÷ 주기의 전체 일수      (기록 없는 날도 포함)
진행 중인 주기: 주기 지출 ÷ 시작일부터 오늘까지의 경과 일수 (오늘 포함)
```

- **경과 1~2일: 일평균을 숨기고 `데이터를 모으는 중이에요`를 표시합니다.** 분모가 1이면 일평균이 오늘 지출과 같아져 오해를 부릅니다.
- 경과 3일 이상부터 표시하며, 가장 가까운 1페소로 반올림합니다.

예: `MX$5,912 ÷ 15일 = MX$394/일`

> 홈의 `오늘 사용 가능 금액`과 결산의 `일평균 지출`은 **서로 다른 값입니다.** 한쪽 숫자를 다른 쪽에 재사용하지 마십시오. 기존 시안 3종이 모두 이 실수를 하고 있었습니다.

## 7. 날짜 기준

> 모든 일일 광고 제한과 엔트리별 적립 날짜는 기기의 로컬 날짜 `YYYY-MM-DD`를 사용하며,
> 타임존 또는 기기 시간 변경을 별도로 보정하지 않는다.

하루 상한용 날짜 키와 엔트리별 날짜 키는 **같은 정의**를 씁니다.

```json
{
  "rewardedAdLastEarnedDate": {
    "character-05": "2026-09-15"
  }
}
```

시계 조작 방어는 하지 않습니다. 광고 횟수 자체는 줄지 않고 보상에 현금 가치도 없으므로 방어 비용이 이득보다 큽니다.

## 7-1. 화면 구조 (시안이 반복해서 틀리는 부분)

탭은 **5개 고정**이며 컬렉션은 탭이 아닙니다.

```dart
// app_shell.dart:20
enum AppTab { home, movements, register, budget, settings }
```

```
홈 · 내역 · ＋ · 예산 · 설정
```

- 어느 화면에서도 이 구성은 바뀌지 않습니다. ＋를 컬렉션으로 대체하지 않습니다.
- 컬렉션은 **설정에서 push로 열리는 별도 화면**입니다 (`settings_screen.dart:121`).
- 컬렉션이 탭에 있으면 2절의 "결산 카드 → 컬렉션으로 이동" 동선이 성립하지 않습니다.

### 금액·기간 라벨

- 결산 블록의 총 지출·남은 금액·일평균은 모두 **주기 단위**입니다. 제목을 `오늘의 결산`으로 쓰면 안 됩니다 → `이번 주기 결산`.
- 화면 목업의 통화는 `$99 MXN` 형식입니다. `MX$`는 이 문서 안에서만 쓰는 표기입니다.

## 10. 시안 체크리스트

시안을 그리거나 검수할 때 대조하는 목록입니다. 시안이 고쳐지면 해당 줄을 지웁니다.

### 1차 시안(₩/$/MXS 혼용본)에서 이미 해결된 것

- ~~강제 전면 광고~~ → 삭제, 결산은 이동 카드만
- ~~광고 금지 화면과 미사용 형식이 한 줄에 섞임~~ → 분리
- ~~일평균 소수점·분모 불일치~~ → `$394 MXN` 정수
- ~~`거래 8건 이후` 규칙을 어긴 배치~~ → 8건 세고 8번째 뒤 삽입
- ~~광고 제거 상품이 v1에 존재~~ → v1.1로 이동, `보유 중` 표시 추가

### 2차 시안에 남아 있는 것

- **하루 한도 표시** → 2절. 한도를 없앴으므로 `하루 최대 3회` 문구와 `오늘 n/3` 표시는 시안에서 빼야 합니다
- **컬렉션이 탭바에 있음** → 7-1절. 탭은 `홈 · 내역 · ＋ · 예산 · 설정` 5개 고정
- **탭 개수가 패널마다 다름** (4개/5개)
- **같은 캐릭터의 해금 조건이 보드마다 다름** (`0/1` ↔ `1/3`)
- **캐릭터가 1회 해금으로 그려짐** → 캐릭터 최솟값은 2회 (2절 티어 표)
- **통화 표기 혼용** (`MX$ 99` ↔ `$99 MXN`) → 화면은 `$99 MXN`
- **`오늘의 결산` 제목에 주기 단위 숫자** → `이번 주기 결산`
- **네이티브 광고에 AdChoices 없음** → 3절 표시 형식
- **v1.1 설정에 `미치와 친구들`이 빠짐**, 상품명이 `광고 제거` → `일반 광고 제거`
- **`계정 없어도 이 기기에서 유지됩니다`** → 복원은 스토어 계정 기반. `구매 항목은 스토어 계정으로 언제든 복원할 수 있어요`
- 오타: `홀` → `홈`, `종도 종료` → `중도 종료`
- 노출 예시의 캐릭터 그림과 이름이 불일치

### 시안의 규칙 박스에 반드시 들어가야 하는 값

규칙 박스에서 빠진 값은 그릴 때마다 달라집니다.

```
v1   1 진입점: 컬렉션 한 곳
     2 성공 집계: 보상 지급 콜백
     3 실패·중도 종료: 보상 없음
     4 아이템 1회 · 일반 캐릭터 2회 · 특별 캐릭터 서로 다른 날 3회
     5 하루 한도 없음 — 카탈로그가 한도

v1.1 1 거래 8건 이상일 때, 8번째 거래 뒤 1회
     2 날짜 헤더는 거래 수에서 제외
     3 실제 노출 시 집계
     4 하루 최대 2회 · 방문당 1회
     5 설치 후 7일 유예
     6 일반 광고 제거는 설정 상점, 팩 구매자는 보유 중
```

## 11. 운영과 미룸

주간 체크리스트는 [admob-ops.md](admob-ops.md)에 있다. Play 지급과 AdMob 지급은 별도 프로필이다.

**지금은 하지 않는다.**

- 앱에 AdSense를 넣지 않는다. AdSense는 웹용이고, 앱은 AdMob만 쓴다.
- iOS AdMob은 iOS 앱·유닛·ATT 문구를 만든 뒤에만 연다. `AdMobConfig.isSupported`가 그 문이다.
- 미디에이션은 일 노출이 수천 단위로 안정된 뒤에만 검토한다.
